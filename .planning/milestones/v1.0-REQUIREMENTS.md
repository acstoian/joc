## Requirement Changes

**PLAY-03 (Modified):** Original spec: "Submitting locks the guest's answer for the round; it cannot be changed." Changed during Phase 5/7 to: answer is optimistically locked but can be re-selected until the host manually locks the round. This matches real-world UX expectations (guests reconsidering) while maintaining fairness (host controls the lock). Server-side UPSERT with ON CONFLICT ensures one answer per player per question in the final scoring. Fairness maintained via WR-01 race handler.

**DISP-08 (Descoped):** "Display supports a host-initiated cosmetic countdown for tension" — the feature was built (CountdownOverlay in Phase 6) but the requirement was descoped in REQUIREMENTS.md because the cosmetic countdown had no practical purpose at a real wedding. The infrastructure exists but is off by default.
