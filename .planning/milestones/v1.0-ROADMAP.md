# Milestone v1.0: Live Wedding Game Show MVP

**Status:** ✅ SHIPPED 2026-06-06
**Phases:** 1–7
**Total Plans:** 27

## Overview

A polished, mobile-first live "A/B trivia" game show web app for a wedding event. Guests join from their phones with just a name, answer host-controlled questions by tapping A or B, and watch live results, reveals, and a leaderboard update in real time. A host drives the entire game flow from a protected dashboard, and a dedicated cinematic Display Mode route projects the action onto a TV/projector for the room. Built on Next.js 15 + Supabase Realtime Broadcast, deployed on Vercel.

**Core Value achieved:** During a live wedding, the room stays in sync and the game feels instant and fun — host actions update every phone and the TV together within ~1s, with no refreshes and no lost players.

## Milestone Summary

**Delivered:** Full live A/B trivia game show — 7 phases, 27 plans, 8,084 lines of TypeScript, 123 commits, 4 days.

**Key Decisions:**
- Supabase Realtime Broadcast (not Postgres Changes) — zero per-subscriber RLS queries on game events; scales to 100+ guests without N×DB queries per host action
- Single service-role client (`admin.ts`) with `server-only` import guard — service key never reaches client bundle, verified with post-build grep in Phase 1
- Host-driven round flow (no auto-timers) — maximum control for a live wedding host; avoids clock-sync complexity
- Guest identity = name + device token (localStorage) — account-free joining with reliable reconnect on flaky mobile connections
- Flat 1-point scoring — simple, fair, inclusive; no speed penalties on slow wedding wifi
- UPSERT (not INSERT) for answers with ON CONFLICT(player_id, question_id) — allows answer changes before host lock; WR-01 race handler preserves fairness
- `useReducedMotion() !== false` guard pattern — `null` on SSR render means confetti must wait for definitive `false` before firing
- `motion` package (not `framer-motion`) — canonical name, full React 19 compatibility

**Issues Resolved:**
- PLAY-03 race condition: check-then-upsert with post-upsert phase re-read and compensating delete/restore
- PLAY-03 seeding: `localAnswerRef.current` snapshot prevents stale server state overwriting optimistic selection on reconnect
- Supabase Realtime StrictMode crash: `createClient()` inside `useEffect` (not `useRef` at module scope)
- Presence ghost entry: `channel.untrack()` before `removeChannel()` is mandatory

**Technical Debt:**
- `getRankClasses`/`getScoreClasses` helpers duplicated in `RevealDisplay.tsx` and `WinnerDisplay.tsx` — extract to shared module if modifying leaderboard styling in v2
- Phase 05 `05-VERIFICATION.md` and Phase 06 `06-VERIFICATION.md` are `human_needed` (attested via production dry run)
- Phase 06 `06-HUMAN-UAT.md` is partial (7 scenarios not formally documented) — production dry run covers all flows

**Deferred to v2:**

- V2-02: Host-issued join code

- V2-04: 4-option question types
