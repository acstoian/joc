<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated client → `GET /api/game/state` | Guests/TV have no auth session; `gameId`/`playerId` are attacker-controllable query params |
| server route → Supabase (service_role via adminClient) | The route holds privileged DB access; must not leak the key or pre-reveal secrets |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | `GET /api/game/state` question read | mitigate | Query `questions_public` view (omits `correct_option`); never read base `questions` table; `correctOption` returned as `null` in Phase 2 (Pitfall 5, ASVS V4) |
| T-02-02 | Tampering / Input | `gameId`/`playerId` query params | mitigate | Validate `gameId` is present and UUID-shaped → 400 on malformed; reject before any DB query (ASVS V5) |
| T-02-03 | Information Disclosure | spoofed `playerId` | accept | Endpoint only returns that player's own `myAnswer` (stub null in Phase 2); no other player's data is reachable via this route; full auth deferred to Phase 3 |
| T-02-04 | Elevation of Privilege | service-role key exposure | mitigate | Route imports only `adminClient` from the `import "server-only"` module; no raw `SUPABASE_SERVICE_ROLE_KEY` reference in the route or in `client.ts` |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed this phase (RESEARCH Package Legitimacy Audit: vacuous — all deps installed in Phase 1) |
</threat_model>
