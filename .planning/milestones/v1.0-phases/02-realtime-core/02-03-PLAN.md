<objective>
Build the throwaway `/sync-demo` harness (D-02) — the visible, end-to-end proof that the Phase 2 sync primitive works. Host-trigger buttons fire each of the 8 GAME_EVENTs through a server action calling the existing `broadcast()` helper; two subscriber panes (each running the real `useGameSync` hook from Plan 02) display connection status, participantCount, last received event type, and the re-fetched authoritative state. This single page exercises the full real path — `useGameSync` → `game:{gameId}` Broadcast channel → `GET /api/game/state` round-trip — and is the surface on which all five Phase 2 success criteria are verified, then removed/replaced when real surfaces arrive in Phases 4–6.

Purpose: A headless hook is unobservable on its own. This harness makes the primitive demonstrable: a human can fire an event in one place and watch two independent subscribers update together within a second (SC1), then simulate a mobile drop (SC2/SC4) and watch them recover. It is the MVP vertical-slice that ties Plans 01+02 into something a person can actually use.

Output: `src/app/actions/demo-broadcast.ts` (new, throwaway) + `src/app/sync-demo/page.tsx` (new, throwaway).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `/sync-demo` client page → `demoBroadcast` server action | The page is a "use client" component; the only way it reaches privileged server code is the Server Action |
| `demoBroadcast` (server) → Supabase Realtime Broadcast REST (service_role) | The action holds the service-role broadcast capability; must stay server-side |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-08 | Elevation of Privilege | service-role key reaching the client bundle | mitigate | `demo-broadcast.ts` is a `"use server"` Server Action; `broadcast()` lives in the `import "server-only"` admin module; the `/sync-demo` page imports the server action (NOT `@/lib/supabase/admin`) — `grep admin` in the page returns 0; the key never enters a client chunk |
| T-02-09 | Tampering | client injecting forged broadcasts onto the channel | accept | Broadcast is fire-from-server in this design; clients subscribe (read) but do not have channel write auth configured — this is a throwaway demo, not a production write path (real host-auth write lands in Phase 3) |
| T-02-10 | Information Disclosure | demo leaking correct answer pre-reveal | mitigate | The panes render only the `GET /api/game/state` snapshot, which reads `questions_public` and stubs `correctOption: null` (Plan 01); ANSWER_REVEALED's live A/B is a demo-only signal, not a DB leak |
| T-02-SC | Tampering | npm installs | accept | No new packages this phase (RESEARCH Package Legitimacy Audit vacuous) |
</threat_model>
