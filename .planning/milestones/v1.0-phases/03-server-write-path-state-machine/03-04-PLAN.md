<objective>
Deliver the reveal+scoring slice and the surgical round-reset slice: `POST /api/host/reveal` (host sets `questions.correct_option` live, runs the idempotent `recompute_scores` RPC, broadcasts `ANSWER_REVEALED` + `SCORES_UPDATED` — HOST-04, SCOR-01) and `POST /api/host/reset` (deletes ONLY the current question's answers and resets phase to `'question'`, broadcasts `ROUND_RESET` — HOST-06). After this plan a host can reveal a question's correct answer and see exactly-1-point-per-correct scoring, and can wipe a single round for a re-answer without corrupting the leaderboard.

Purpose: Reveal is the scoring boundary. Per D-09 scoring is recomputed from scratch on every reveal (never incremented), so the `correct_option` UPDATE must be UNCONDITIONAL (overwrites a prior value after a reset — Pitfall 5) and the `recompute_scores` RPC (Plan 01, migration 0004) makes reset+re-reveal double-count-proof (Pitfall 4). Round reset is surgical (D-08): it is explicitly NOT `reset_game()` (the full-wipe → lobby path reserved for dry-runs / Phase 4) — it deletes only `current_question_id`'s answers and returns phase to `'question'`. Both routes gate on Plan 01's `validateHostAuth`. This plan owns only the reveal + reset files, so it runs in Wave 2 parallel with Plan 03 (transition).

Output: `src/app/api/host/reveal/route.ts` (new), `src/app/api/host/reset/route.ts` (new).
</objective>

|----------|-------------|
| host client → `/api/host/reveal`, `/api/host/reset` | Host sends the shared password header; an attacker may forge or omit it |
| server route → questions.correct_option / answers / scores / SECURITY DEFINER RPC | Privileged write surface that decides the correct answer and the score totals |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-12 | Elevation of Privilege | forged reveal/reset request without password | mitigate | `validateHostAuth(req)` is the first statement on both routes; 401 + no mutation (HOST-01, SC3, ASVS V2/V4) |
| T-03-13 | Tampering | score double-count on re-reveal or reset+re-reveal | mitigate | `recompute_scores` RPC counts from scratch (D-09); reveal sets `correct_option` unconditionally so a re-reveal overwrites cleanly (Pitfall 4/5) |
