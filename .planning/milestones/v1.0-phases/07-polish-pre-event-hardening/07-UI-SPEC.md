> covering the aesthetic and animation upgrades that deliver the soft-luxury wedding feel.

### Animation 1: AnimatePresence — TV Phase Screen Transitions (D-01, D-02)

**File:** `src/app/display/page.tsx`

**Scope:** TV display only. Guest app does not receive AnimatePresence.

**Pattern:** Wrap the `screen` variable in `<AnimatePresence mode="wait">`. Each screen component
is a `motion.div` with `variants` matching the existing CSS keyframes (`slide-up`, `fade-scale`).

```tsx
import { AnimatePresence, motion } from "motion/react";

// In DisplayPage render:
<AnimatePresence mode="wait">
  <motion.div
    key={state?.phase ?? "loading"}
    variants={{
      hidden:  { opacity: 0, y: "2vh" },
      visible: { opacity: 1, y: 0 },
      exit:    { opacity: 0, y: "-1vh" },
    }}
    initial="hidden"
    animate="visible"
    exit="exit"
    transition={{ duration: 0.35, ease: "easeInOut" }}
    style={{ width: "100%", height: "100%" }}
  >
    {screen}
  </motion.div>
</AnimatePresence>
```

**Key rule:** `key={state?.phase ?? "loading"}` — AnimatePresence triggers on phase change.
When the host transitions phases, the old screen slides up and fades out (exit), then the new
screen slides up and fades in (enter). `mode="wait"` ensures no overlap.

**Reduced-motion fallback:**
```tsx
import { useReducedMotion } from "motion/react";

// Inside DisplayPage:
const shouldReduce = useReducedMotion();

// Pass to AnimatePresence wrapper:
transition={{ duration: shouldReduce ? 0 : 0.35, ease: "easeInOut" }}
// Or conditionally omit variants when shouldReduce is true:
// initial={shouldReduce ? false : "hidden"}
// animate={shouldReduce ? false : "visible"}
// exit={shouldReduce ? undefined : "exit"}
```

**Duration:** 350ms enter, 300ms exit (implicit from `mode="wait"` exit matching transition).
**Properties animated:** `opacity` + `transform: translateY` — compositor-safe, no layout trigger.

### Animation 2: Staggered Leaderboard Rows (D-03)

**Files:** `src/components/display/RevealDisplay.tsx`, `src/components/display/WinnerDisplay.tsx`

**Scope:** TV display leaderboard only. `LeaderboardPanel` used on the guest surface is not
modified (no stagger on guest — reliability priority on low-end phones).

**Pattern:** Replace the `<LeaderboardPanel>` call in both display components with an inline
staggered list. Read `LeaderboardPanel.tsx` before implementing to extract the row structure —
duplicate the markup but wrap each row in `motion.div`.

**Stagger variant specification:**

```tsx
const containerVariants = {
  hidden: {},
  visible: {
    transition: {
      staggerChildren: 0.08,
      delayChildren: 0.1,
    },
  },
};

const rowVariants = {
  hidden: { opacity: 0, y: 10 },
  visible: {
    opacity: 1,
    y: 0,
    transition: { duration: 0.25, ease: "easeOut" },
  },
};

// In JSX:
<motion.ul
  variants={containerVariants}
  initial="hidden"
  animate="visible"
>
  {leaderboard.map((player, i) => (
    <motion.li key={player.id} variants={rowVariants}>
      {/* row content — identical to LeaderboardPanel row */}
    </motion.li>
  ))}
</motion.ul>
```

**Stagger math:** 10 rows × 80ms = 800ms total stagger. This produces the "building to #1" feel
when the leaderboard is shown top-to-bottom (rank 1 appears after all lower-rank entries are
visible — mount order is rank 1 first, so rows stagger top-to-bottom naturally).

**Trigger:** The stagger runs once on `RevealDisplay` mount and once on `WinnerDisplay` mount.
Because `AnimatePresence mode="wait"` is in place, the leaderboard animates fresh on each
transition into `revealed` or `ended` phase. It does NOT re-run on every score tick (the
component does not re-mount for score updates within a phase).

**Reduced-motion fallback:**
```tsx
const shouldReduce = useReducedMotion();
// If shouldReduce: render plain <ul>/<li> without motion wrappers
```

### Animation 3: Guest A/B Tap Feedback (D-04)

**File:** `src/components/guest/QuestionScreen.tsx`

**Scope:** Guest surface only. The `<button>` element for each A/B option is converted to
`motion.button` (or wrapped in `motion.div`) to enable `whileTap`.

**Exact specification:**

```tsx
import { motion } from "motion/react";

// Replace <button type="button" className={getButtonClass(...)} onClick={...}>
// With:
<motion.button
  type="button"
  className={getButtonClass("A", localAnswer, state.phase)}
  onClick={() => handleTap("A")}
  whileTap={{ scale: 0.96 }}
  transition={{ duration: 0.1, ease: "easeOut" }}
  aria-pressed={localAnswer === "A"}
  aria-disabled={isLocked && localAnswer !== "A"}
  aria-label={`Opțiunea A: ${q?.optionA ?? "A"}`}
>
```

**Preservation requirements:**
- `touch-action: manipulation` must be preserved — it is set via `[touch-action:manipulation]`
  Tailwind class on `baseLayout` inside `getButtonClass`. The class must remain present on
  `motion.button`.
- `pointer-events-none` on locked/unselected state must be preserved. `motion.button` respects
  CSS `pointer-events` normally.
- `focus-visible:ring-2 focus-visible:ring-gold/50` — preserve on `motion.button`.
- When `localAnswer !== null` (locked), `whileTap` still fires visually but `onClick` is no-op
  due to the `if (localAnswer !== null) return;` guard. This is acceptable — the scale tap
  provides tactile confirmation that the phone registered the touch.

**Reduced-motion fallback:**
```tsx
const shouldReduce = useReducedMotion();
// Conditionally apply whileTap:
whileTap={shouldReduce ? undefined : { scale: 0.96 }}
```

### Animation 4: Correct-Answer Confetti — Guest RevealScreen (D-08)

**File:** `src/components/guest/RevealScreen.tsx`

**Trigger:** `state.playerAnsweredCorrectly === true` (from `GameStateSnapshot`). Fires once on
`RevealScreen` mount when the player's answer matches the correct option.

**Implementation pattern (copy from `WinnerScreen.tsx` — ref-guard + dynamic import):**

```tsx
import { useEffect, useRef } from "react";

const confettiFired = useRef(false);

useEffect(() => {
  if (!state.playerAnsweredCorrectly) return;
  if (confettiFired.current) return;
  confettiFired.current = true;

  import("canvas-confetti").then(({ default: confetti }) => {
    confetti({
      particleCount: 60,
      spread: 50,
      origin: { y: 0.6 },
      colors: ["#f0c060", "#f5e6c8", "#d4a843"],
    });
  });
}, []);
// Note: empty deps — fires once on mount. state.playerAnsweredCorrectly checked inside,
// not in deps, to preserve the ref-guard single-fire contract.
```

**Particle specification (D-08, locked):**
- `particleCount: 60`
- `spread: 50`
- `origin: { y: 0.6 }`
- `colors: ["#f0c060", "#f5e6c8", "#d4a843"]` (gold + champagne, no blush — smaller burst)

**Performance contract:**
- Dynamic import — `canvas-confetti` is NOT in the initial bundle for `RevealScreen`
- Fires exactly once per correct reveal (ref guard)
- No confetti on incorrect reveal (guard: `if (!state.playerAnsweredCorrectly) return`)

**Field name verification:** Check `src/hooks/useGameSync.ts` for the exact field name on
`GameStateSnapshot` before implementing. The CONTEXT.md references `playerAnsweredCorrectly`.
If the field has a different name (e.g. `myAnswerWasCorrect`), use the actual field name.

**Reduced-motion:** No reduced-motion override for confetti — it is a one-shot imperative call
with no CSS animation. The ref-guard ensures it fires once regardless. If the user's OS has
reduced-motion enabled, skip the confetti entirely:
```tsx
const shouldReduce = useReducedMotion();
// Add to guard: if (shouldReduce) return;
```

### Animation 5: Winner Confetti — TV WinnerDisplay (D-09)

**File:** `src/components/display/WinnerDisplay.tsx`

**Trigger:** Component mounts when `state.phase === "ended"`. Fires once on mount.

**This overrides the Phase 6 UI-SPEC note** ("No confetti on WinnerDisplay") — D-09 in
07-CONTEXT.md explicitly adds confetti here for the room-wide celebration moment.

**Implementation pattern (same as WinnerScreen.tsx and RevealScreen confetti):**

```tsx
import { useEffect, useRef } from "react";

const confettiFired = useRef(false);

useEffect(() => {
  if (confettiFired.current) return;
  confettiFired.current = true;

  import("canvas-confetti").then(({ default: confetti }) => {
    confetti({
      particleCount: 150,
      spread: 100,
      origin: { x: 0.5, y: 0.3 },
      colors: ["#f0c060", "#f5e6c8", "#d4a843", "#e8a0a0"],
    });
  });
}, []);
```

**Particle specification (D-09, locked):**
- `particleCount: 150`
- `spread: 100`
- `origin: { x: 0.5, y: 0.3 }` — upper-center of landscape screen, falls naturally downward
- `colors: ["#f0c060", "#f5e6c8", "#d4a843", "#e8a0a0"]` (gold + champagne + blush — full room burst)

**TV origin rationale (D-09 specifics):** Firing from `y: 0.3` (upper third of the screen)
rather than `y: 0.6` (bottom-up) suits a landscape projector — confetti falls down across the
full display.

**Reduced-motion:** Same pattern as RevealScreen confetti:
```tsx
const shouldReduce = useReducedMotion();
if (shouldReduce) return; // skip confetti
```
