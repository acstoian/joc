<objective>
Deliver the guest write slice end-to-end: `POST /api/game/join` (idempotent player upsert — JOIN-01/02/03) and `POST /api/game/answer` (phase-guard 403 + DB dedup 409 + server-side identity binding — SCOR enforcement, anti-cheat). After this plan a guest can register and submit exactly one answer per question, with the DB rejecting late and duplicate answers — both routes are independently verifiable with `curl` against the Phase 1 seed game.

Purpose: This is the guest half of the authoritative write path. Join is idempotent so a refresh/reconnect re-links the same player by device_token (JOIN-03). The answer route is the phase's anti-cheat surface: it resolves `player_id` server-side from the submitted `device_token` (a guest never holds another player's id), the `UNIQUE(player_id, question_id)` constraint blocks replays (23505→409), and the phase guard blocks late answers (phase != 'question' → 403). It has zero file overlap with Plan 01 and depends on nothing — it runs in parallel in Wave 1.

Output: `src/app/api/game/join/route.ts` (new), `src/app/api/game/answer/route.ts` (new).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated guest → `/api/game/join`, `/api/game/answer` | Guests have no auth session; all body fields (gameId, deviceToken, displayName, choice) are attacker-controllable |
| server route → Supabase (service_role via adminClient) | Privileged write surface; anon RLS blocks direct INSERT so the route is the only write path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | Spoofing | guest submits an answer as another player | mitigate | Answer body carries `deviceToken` NOT `player_id`; route resolves `player_id` server-side from `(game_id, device_token)` so a guest cannot forge another player's id (Pattern 4, ASVS V4) |
| T-03-05 | Tampering | duplicate / replayed answer submission | mitigate | `UNIQUE(player_id, question_id)` DB constraint; `error.code === "23505"` → 409; no second row created (SCOR-03) |
| T-03-06 | Tampering | late answer after host lock | mitigate | Layer 1 phase guard reads `games.phase` server-side; `phase !== "question"` → 403 before any INSERT (SCOR-04) — client-claimed phase is never trusted |
| T-03-07 | Input Validation | malformed gameId/deviceToken/choice or oversized/empty name | mitigate | UUID-shape validation → 400; `choice` ∈ {A,B} → 400; name trim+non-empty+≤30, unicode allowed → 400 on empty/oversize (ASVS V5, D-04) |
| T-03-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed this phase (RESEARCH Package Legitimacy Audit: zero new deps) |
</threat_model>
