<objective>
Close GAP-04-01: once a game reaches the terminal `ended` phase there is NO host control to start a new game or return to `lobby`. The Phase 3 state machine has no `* -> lobby` transition (`start` requires `expectedFrom: lobby`; `/api/host/reset` is only valid from question/locked/revealed), so after "Incheie Jocul" / force-end both "Porneste Jocul" and "Reseteaza Runda" are correctly disabled/no-op — leaving the host stuck with no UI path to play again. This undermines HOST-11 (emergency recovery: "recover a stuck game"), since an ended/accidentally-ended game is exactly such a state.

Fix: add a host-auth-gated `reset_game` capability that returns the whole game to a fresh lobby, then wire a confirm-gated "Joc Nou / Reseteaza Jocul" control into the EmergencyPanel — DISTINCT from the existing round-only "Reseteaza Runda".

Purpose: HOST-11 must let the host recover from ANY stuck state, including `ended`. Without a return-to-lobby path the dashboard cannot run a second game without a manual DB edit (the UAT workaround).

Output: a new `reset_game` action on `POST /api/host/transition` and a new destructive control in `EmergencyPanel.tsx`. No schema changes, no new GameEvent union member — the `reset_game(p_game_id)` SQL function (migration 0003) and the existing `GAME_ENDED` event already exist and are reused.
</objective>
