<objective>
Establish the guest-app foundation and deliver the first vertical slice of the guest journey: a guest opens the bare domain, enters their name, and lands in a live lobby showing the participant count and a join QR code — surviving refresh via a persistent device token.

Purpose: This plan replaces the throwaway `sync-demo` root page with the real GuestShell, installs the two UI packages the phase needs, adds the missing `NEXT_PUBLIC_APP_URL` env var, and builds the shared primitives (identity helpers, status badge, leaderboard panel) every later screen consumes. It also stands up the full phase switch in `page.tsx` so subsequent plans only add their own screen files without re-touching the shell.

Decision coverage (CONTEXT.md): D-01 (guest app at root `/`, replacing sync-demo), D-02 (GAME_ID from NEXT_PUBLIC_GAME_ID; QR encodes NEXT_PUBLIC_APP_URL), D-03 (full-screen name gate on first load; returning guests skip to the game view), D-07 (single page, conditional render per `state.phase` — no routing segments, no AnimatePresence), D-10 (name-gate visual: centered glass card, Playfair heading, "Joacă!" submit, Romanian inline errors), D-11 (QR code in lobby via react-qr-code), D-12 (non-blocking SyncStatusBadge top badge driven by SyncStatus).

Output: A working join → lobby slice (JOIN-04, JOIN-05) plus the foundation (identity.ts, SyncStatusBadge, LeaderboardPanel, GuestShell switch) that 05-02 and 05-03 build on.
</objective>
