## Orientation & Viewport

The `/display` route is **landscape-only** (TV/projector). Design all layouts assuming:
- Viewport: approximately 1920×1080 or similar 16:9 landscape ratio
- Reading distance: 3–4 metres — all text sized in viewport units (`vw`, `vh`, `vmin`) not `px`
- No mobile breakpoints required for this route (guest app covers mobile)
- Baseline: `min-h-dvh w-screen overflow-hidden bg-ink`

**Typography uses viewport-relative units on this route only.** Pixel values below are approximate
equivalents at 1920px wide for orientation; implementor uses `vw`/`vmin` units.

## Typography

The display surface uses **viewport-relative font sizing**. All text must be readable from
3–4 metres at a 1080p or 4K projection.

**Four roles, two weights.** Every element on the display route uses exactly one of these four
roles. No additional viewport-relative sizes are permitted outside this table.

| Role | Font | Size (viewport units) | ~px at 1920px | Weight | Line Height | Tailwind |
|------|------|-----------------------|---------------|--------|-------------|---------|
| Label | Inter (`font-body`) | `text-[1.5vw]` | ~29px | 400 (regular) | 1.4 | `text-[1.5vw] font-normal font-body` |
| Body | Inter (`font-body`) | `text-[2vw]` | ~38px | 400 (regular) | 1.5 | `text-[2vw] font-normal leading-normal font-body` |
| Heading | Playfair Display (`font-heading`) | `text-[4vw]` | ~77px | 700 (bold) | 1.2 | `text-[4vw] font-bold leading-tight font-heading` |
| Display | Playfair Display (`font-heading`) | `text-[6vw]` | ~115px | 700 (bold) | 1.15 | `text-[6vw] font-bold font-heading` |

**Role absorption rules (checker reference):**
- Label (`text-[1.5vw]`) absorbs all 1.x sizes — including any sub-label or status indicator text
- Body (`text-[2vw]`) absorbs 2.x sizes — A/B option text, percentage labels, leaderboard rows
- Heading (`text-[4vw]`) absorbs 3.x sizes — leaderboard headings, sub-headings, "Clasament final"
- Display (`text-[6vw]`) absorbs 5.x sizes — question text and winner name both use Display role

**Special role — countdown number (one-off exception, not a 5th scale entry):**
- This single element requires full-screen dominance and is architecturally unique (a modal overlay
  with no surrounding context). It is explicitly exempt from the 4-role constraint.
- Font: Playfair Display (`font-heading`)
- Size: `text-[20vw]` (~384px at 1920px wide)
- Weight: 700 (bold)
- Color: `text-gold-bright`
- Tailwind: `text-[20vw] font-bold font-heading text-gold-bright`
- **Permitted only in:** `CountdownOverlay.tsx` — no other component may use `text-[20vw]`

**Applied-by-screen table — all classes use only the 4 named roles:**

|---------|------|---------|

## Screen-by-Screen Visual Contract

### DisplayPage Shell

**Route:** `src/app/display/page.tsx`
**Client component** (`"use client"`) — calls `useGameSync(GAME_ID, null)`.

**Shell layout:**
```
div  // root container — ref for requestFullscreen
  className="relative min-h-dvh w-screen overflow-hidden bg-ink"
  ref={containerRef}

  ├── DisplayStatusDot  // fixed top-right, z-50
  ├── FullscreenButton  // fixed top-right (above status dot), z-50 — disappears on enter
  ├── CountdownOverlay  // fixed inset-0, z-40 — conditional, above screen content
  └── [Phase screen]   // fills remaining space — switch on state.phase
        lobby     → <LobbyDisplay />
        question  → <QuestionDisplay />
        locked    → <LockedDisplay />
        revealed  → <RevealDisplay />
        ended     → <WinnerDisplay />
        null      → <LoadingDisplay /> (state not yet loaded)
```

**Fullscreen button:**
```
<button
  onClick={() => containerRef.current?.requestFullscreen()}
  className="fixed top-4 right-4 z-50 glass rounded-lg px-4 py-2 text-[1.5vw] font-body
             text-champagne-dim hover:text-champagne transition-opacity duration-300
             [document.fullscreenElement && 'opacity-0 pointer-events-none']"
  aria-label="Activează ecran complet"
>
  Ecran complet
</button>
```

Hides via `opacity-0 pointer-events-none` when `document.fullscreenElement !== null` (derived
from `document.fullscreenchange` event listener in a `useEffect`). Not unmounted — retains
DOM position for graceful fallback.

**Phase switch (conditional render — no AnimatePresence in Phase 6):**
```typescript
// Simple conditional render — Phase 7 upgrades to AnimatePresence
if (!state) return <LoadingDisplay />;
switch (state.phase) {
  case "lobby":    return <LobbyDisplay participantCount={participantCount} />;
  case "question": return <QuestionDisplay state={state} />;
  case "locked":   return <LockedDisplay state={state} />;
  case "revealed": return <RevealDisplay state={state} />;
  case "ended":    return <WinnerDisplay state={state} />;
}
```

  │     │          ← "{participantCount}"
  │     └── span  className="text-[1.5vw] font-normal font-body text-champagne-dim"
  │                ← "jucători s-au alăturat"

          ← "Așteptăm să înceapă..."

**Pulse implementation (count change):**
The participant count number uses a CSS `animate-pulse` class that is toggled for 600ms when
`participantCount` changes. Implementation: `useEffect([participantCount])` sets a `pulsing`
boolean for 600ms via `setTimeout`. Does not use `motion/react`.

```typescript
const [pulsing, setPulsing] = useState(false);
useEffect(() => {
  setPulsing(true);
  const t = setTimeout(() => setPulsing(false), 600);
  return () => clearTimeout(t);
}, [participantCount]);
```

Class on count span: `cn("text-[4vw] font-bold font-heading text-champagne", pulsing && "animate-pulse")`.

### Overlay: CountdownOverlay

**Trigger:** `COUNTDOWN_STARTED` event received from `useGameSync` (D-09, DISP-08).

**Behavior:** Client-side `setInterval` counts down from `seconds` (= 3) to 0, decrementing
every 1000ms. When `count` reaches 0, the overlay unmounts.

**State management (inside DisplayPage shell):**
```typescript
const [countdown, setCountdown] = useState<number | null>(null);

// In COUNTDOWN_STARTED handler (useEffect on state changes or event bus from useGameSync):
// setCountdown(3);

useEffect(() => {
  if (countdown === null || countdown <= 0) return;
  const t = setInterval(() => {
    setCountdown((c) => (c !== null && c > 1 ? c - 1 : null));
  }, 1000);
  return () => clearInterval(t);
}, [countdown]);
```

**Layout:**
```
div  // fixed overlay
  className="fixed inset-0 z-40 flex items-center justify-center
             bg-ink/80 backdrop-blur-sm"

  └── span  className="text-[20vw] font-bold font-heading text-gold-bright
                        leading-none select-none
                        [animation: fade-scale 200ms ease-out]"
             key={countdown}  // re-mounts the element on each tick to re-trigger animation
             ← "{countdown}"  // "3", "2", "1"
```

**Tick animation (CSS, applied via key re-mount):**
```css
@keyframes fade-scale {
  from { opacity: 0.4; transform: scale(0.8); }
  to   { opacity: 1;   transform: scale(1); }
}
```

**Does not block `useGameSync`:** The overlay is rendered above the screen content via `z-40`.
The phase-switch rendering below the overlay continues to update normally — when the host advances
the phase during or after the countdown, the underlying screen is already showing the new state.

**Note on `COUNTDOWN_STARTED` event routing:** `useGameSync` returns `state: GameStateSnapshot`,
not raw events. The planner must decide how `COUNTDOWN_STARTED` surfaces to the display component
— either by extending `useGameSync` to return the last broadcast event, by adding a callback
prop, or by using a Zustand atom as a one-shot trigger. This is an implementation decision for
the planner; the UI contract requires only that the countdown triggers when `COUNTDOWN_STARTED`
is received and runs client-side via `setInterval`.

## Animation Contract

Source: 06-CONTEXT.md D-07 — functional transitions only in Phase 6. No AnimatePresence, no
staggered sequences. Phase 7 upgrades to full cinematic.

| Transition | Implementation | Duration |
|-----------|----------------|----------|
| Phase screen switch | Conditional render (`switch` on `state.phase`) — instant | 0ms |
| Question text entry | CSS `@keyframes slide-up` via class on `h2`, key=questionId | 400ms |
| A/B bar fill (locked) | `transition-[width] duration-500 ease-out` on fill div | 500ms |
| Correct bar scale on reveal | `scale-[1.03] transition-transform duration-300` — class applied at render | 300ms |
| Correct bar glow on reveal | CSS `box-shadow` applied at render (no animation — instant) | instant |
| Wrong bar dim on reveal | `opacity-40 transition-opacity duration-300` on wrapper | 300ms |
| Countdown number tick | CSS `@keyframes fade-scale` via key re-mount per tick | 200ms |
| Lobby participant count pulse | `animate-pulse` toggled for 600ms via setTimeout | 600ms |
| Fullscreen button hide | `opacity-0` CSS — triggered by `fullscreenchange` event | instant |
| CountdownOverlay mount/unmount | Conditional render — instant | 0ms |

**All animations use only:** `opacity`, `transform` (scale, translateY) — no layout-triggering
properties (`width` exception on bars is safe — width is a known compositor-fallback).

**Reduced-motion compliance (inherited from globals.css):**
```css
@media (prefers-reduced-motion: reduce) {
  .animate-pulse { animation: none; }
  /* slide-up and fade-scale keyframes should also respect this */
  @keyframes slide-up { from { opacity: 1; transform: none; } to { opacity: 1; transform: none; } }
  @keyframes fade-scale { from { opacity: 1; transform: none; } to { opacity: 1; transform: none; } }
}
```
